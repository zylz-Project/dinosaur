# AI恐龙萌宠完整动作说明 V3.3

本文逐一说明当前固件中的全部动作，包括29个互动动作变体、5个长环境音场景、4个待机生命动作、基础待机姿态、PCM实时声音驱动以及随机表演叠加层。

动作实现在 `main/auto_run.cc`，外部接口定义在 `main/auto_run.h`。

## 1. 五路舵机基准

| GPIO | 部位 | 角度方向 | 软件范围 |
| --- | --- | --- | --- |
| IO15 | 头部左右 | 0°最右，90°朝正前方，180°最左 | 0°～180° |
| IO16 | 脖子左右 | 0°向右，90°中位，180°向左 | 0°～180° |
| IO17 | 脖子上下 | 0°最上/仰天，90°中位，180°最下/进食 | 0°～180° |
| IO8 | 尾巴上下 | 55°最下安全位，90°中位，180°最上 | 55°～180° |
| IO18 | 尾巴左右 | 0°最左，90°中位，180°最右 | 0°～180° |

默认平静姿态使用 `IO17=70°`，即比几何中位90°抬高20°。这样上电和无互动待机时会保持较精神的长颈轮廓；90°仍然是机械中位，进食、撒娇和困倦动作可以继续向下使用完整行程。

头部和尾巴左右轴动作结束后都会缓慢回到90°。动作可以随机镜像，因此下文所说的“左侧”或“右侧”在实机上可能反向出现。

为了让编舞代码保持“数值越小尾巴越高”的直观语义，动作段落中的尾巴上下数值使用内部 `TUD`：`TUD=0`表示最高，`TUD=125`表示最低；输出到实机时自动换算为 `IO8=180-TUD`。Web滑块和第一节硬件表使用真实IO8角度。

关键帧还会叠加随机力度、速度和表演风格，文中的角度用于说明编舞意图，不代表每次输出完全相同。

## 2. 公共动作规则

每个互动动作都遵循以下流程：

1. 用约260毫秒把头部转回90°，先与正前方用户建立联系；
2. 随机选择当前情绪的一套动作变体；
3. 随机选择镜像方向、速度、力度、脖子风格、头部视线和尾巴风格；
4. 使用Catmull-Rom连续曲线通过关键姿态；
5. 动作结束后用0.8～1.9秒缓慢收势；
6. IO15头部和IO18尾巴左右轴回到90°，再进入有机待机。

下表“主体时长”只计算关键帧，不包含260毫秒注意前奏、随机变速和最后收势。

## 3. 发现用户 `DINO_ACTION_DISCOVER`

适用：开机问候、人脸出现、唤醒词、用户靠近、短促疑问叫声。

### 3.1 正面发现 `discover-direct`

- 主体时长：约2.53秒。
- 故事：小头先发现动静，冻结确认，整条长颈随后检查两侧，最后判断用户安全并主动前探。
- 头部：140毫秒内先转向目标，颈部横扫时做反向补偿，结束回90°看用户。
- 脖子：先抬高，再从约150°一侧跨过90°到约34°另一侧，最后IO17前探到约108°。
- 尾巴：先上提到约28°～32°警戒，再在颈部反方向配重，最后左右回90°。
- 亮点：顺序明确地表现“头先看到—脖子跟随—尾巴响应”，不会五路同时启动。

### 3.2 谨慎偷看 `discover-peek`

- 主体时长：约2.51秒。
- 故事：胆小地缩回去，从一侧偷看，再检查另一侧，最后鼓起勇气靠近。
- 头部：先快速看向一侧，之后与长颈反向观察，像从脖子旁边探出来。
- 脖子：IO17回收到约48°形成守备姿态，IO16随后从约146°跨到约36°，最后前探到约116°。
- 尾巴：后缩时明显上提并绷住，确认安全后才放松。
- 亮点：比正面发现更慢、更谨慎，体现幼龙不同性格。

### 3.3 仰望追踪 `discover-sky-track`

- 主体时长：约3.07秒。
- 故事：小头先发现高处目标，IO17随后仰起，整条长颈从天空一侧追到另一侧，最后重新低头看主人。
- 头部：IO15先到约166°，长颈启动后跨过90°到约24°，最后先于脖子回正。
- 脖子：IO17到约8°仰望；IO16从约174°完整跨到约6°，充分使用两路长颈范围。
- 尾巴：头颈已经追踪后才启动，从一侧跨过90°到另一侧，并改变高度进行配重。
- 亮点：与前两套地平线发现不同，完整表现“看到天空动静”的长颈恐龙特色。

## 4. 亲近互动 `DINO_ACTION_AFFECTION`

适用：摸头、触摸传感器、抱起、连续互动、用户说“贴贴”。

### 4.1 长颈低头问候 `affection-neck-bow`

- 主体时长：约2.82秒。
- 故事：先与用户对视，再低下长颈和额头，安静等待用户抚摸。
- 头部：先保持90°正面视线，低头时只做小幅补偿，靠近后再次抬头确认用户。
- 脖子：IO17从约104°逐渐下探到142°、164°，在约150°低位停留后抬起。
- 尾巴：高位保持或反向配重，左右只有轻柔变化。
- 亮点：最有“主动邀请摸头”感觉的互动动作。

### 4.2 侧面缓慢靠近 `affection-gentle-reach`

- 主体时长：约3.24秒。
- 故事：从一侧走大弧靠近用户，在低位安静停留，然后从另一侧退出。
- 头部：先发现侧面目标，靠近用户时重新稳定到90°附近。
- 脖子：IO16由约66°走到142°，IO17下探到约170°；停留后从另一侧缓慢撤回。
- 尾巴：上翘到约24°～42°，大多与长颈反方向保持平衡。
- 亮点：完整展示两路拉线长颈的二维大空间运动。

### 4.3 猫式脸颊轻蹭 `affection-playful-nuzzle`

- 主体时长：约2.74秒。
- 故事：把一侧脸颊送给用户，跨过正面轻蹭一次，再俏皮回头。
- 头部：从约72°跨到138°，与脖子配合形成一次连续轻蹭，随后回望用户。
- 脖子：IO16从约132°跨过90°到约48°；IO17保持126°～150°的靠近低位。
- 尾巴：可以从约42°跨到148°，也可能随机叠加快速摇尾或空间圆。
- 亮点：保留熟悉的猫式萌宠表达，但只是四套亲近动作中的随机惊喜，不会每次重复。

### 4.4 害羞低头贴近 `affection-shy-approach`

- 主体时长：约3.56秒。
- 故事：幼龙先把脖子缩高偷看，确认主人友好后突然把整条长颈放低到手边，安静等待触摸。
- 头部：IO15先去约18°侧看，低位贴近时回90°正面，离开前再做一次小回望。
- 脖子：先抬到IO17约28°，再一次大弧下探到176°～180°；IO16沿另一条路径撤回。
- 尾巴：靠近期间先保持高位，用户接触后才做一次延迟跨中位回应，不与脖子同步起动。
- 亮点：既有猫式害羞，也把长颈的完整上下行程变成一次可读的人机互动。

## 5. 开心雀跃 `DINO_ACTION_HAPPY`

适用：识别到主人、获得奖励、完成任务、连续触摸、开心短叫。

### 5.1 幼龙昂首展示 `happy-juvenile-display`

- 主体时长：约2.52秒。
- 故事：昂起长颈展示自己，完整巡视两侧，再兴奋地向用户靠近。
- 头部：幅度小于长颈，主要负责观察和反向补偿。
- 脖子：IO17先抬到约54°；IO16由154°跨到28°；最后IO17前探到约142°。
- 尾巴：保持约20°～30°高位，可随机选择快速宽扫、画圆或反向配重。
- 亮点：先形成长颈恐龙剪影，再加入萌宠式靠近。

### 5.2 长颈跨身宽扫 `happy-long-neck-sweep`

- 主体时长：约2.82秒。
- 故事：从高位沿一条大对角线走到另一侧低位，然后重新昂首。
- 头部：与脖子错向观察，不跟着长颈同幅度同步摆动。
- 脖子：从IO17约42°高位出发，IO16展开到166°；随后IO17到158°、IO16跨到34°。
- 尾巴：始终在头颈反方向大幅配重，并保持明显上翘。
- 亮点：幅度很大，但只做少量宽弧反向，不用机械式快速来回抖动。

### 5.3 招牌空间画圆 `happy-orbit`

- 主体时长：约2.52秒。
- 故事：柔性长颈完成一圈大空间轨迹，尾巴走不同相位的反向椭圆。
- 头部：只做较小视线补偿，不与脖子共用同一幅度和相位。
- 脖子：IO17与IO16相差约四分之一圈，经过高、低、左、右多个接近全行程的位置。
- 尾巴：IO8与IO18组成第二条空间轨迹，方向和相位与脖子错开。
- 亮点：这是展示产品360度柔性运动创新的招牌动作，随机出现且不会持续循环。

### 5.4 幼龙追尾游戏 `happy-tail-chase`

- 主体时长：约3.26秒。
- 故事：小头突然发现自己的尾巴，长颈追过去，尾巴最后逃开；停一下后又从另一条对角线追一次。
- 头部：先单独接近IO15一端，再跨过90°追向相反方向，动作结束严格回到90°朝前。
- 脖子：IO16经过约176°和22°两端，IO17同时经历高位和低位，但两路换向时刻不同。
- 尾巴：作为主角最后启动，IO18在同一动作内接近18°和176°两侧；IO8配合做高低弧线。
- 亮点：不是普通摇尾，而是有“发现—追逐—逃开—再追”的幼龙游戏故事。

## 6. 威风鸣叫 `DINO_ACTION_PROUD_CALL`

适用：较长恐龙叫声、主动吸引用户、产品展示高潮。

四套鸣叫动作都支持长音频续演。音频未结束时会换到不同片段、方向、力度和速度，不会重复刚完成的动作。

### 6.1 正面蓄力鸣叫 `proud-front`

- 主体时长：约3.35秒。
- 故事：后仰吸气，短暂停顿，向前发声，再巡视两侧确认用户反应。
- 头部：蓄力时正面稳定，发声后分别确认左右两侧。
- 脖子：IO17先抬到约34°蓄力，再到0°仰天长啸并保持约520毫秒。
- 尾巴：高高翘起，并在发声冲击时做反向平衡。
- 亮点：叫声前有明显“吸气—停顿—发力”的时间结构。

### 6.2 斜向鸣叫与巡视 `proud-sweep`

- 主体时长：约3.86秒。
- 故事：从斜侧蓄力，沿对角线鸣叫，再用长颈巡视领地。
- 头部：先与蓄力方向一致，冲击后独立确认另一侧。
- 脖子：IO17先到0°仰天、IO16保持斜侧姿态，随后跨过90°中位完成大范围巡视。
- 尾巴：偏向空间画圆、高位保持和动态配重。
- 亮点：比正面鸣叫更有侧向空间感。

### 6.3 长叫声全空间展示 `proud-orbit`

- 主体时长：约4.86秒。
- 故事：围绕长叫声完成“抬头—展开—低位—两次凝视—重新确认”的完整表演。
- 头部：在两个方向各有一次约300毫秒的凝视，不会一直匀速摆动。
- 脖子：IO17先到0°完成仰天长啸，再与IO16经过多组接近全行程的高低左右姿态。
- 尾巴：在不同高度和方向动态配重，而非固定保持一种摇摆。
- 亮点：适合长叫声中段做全空间展示，不在原地保持一个动作族。

### 6.4 双段仰天回应 `proud-echo-call`

- 主体时长：约4.06秒。
- 故事：第一次正面仰天长啸，横跨两侧确认主人反应后，再从另一侧做一次较短的回应叫。
- 头部：第一次叫声保持正面；中间巡视时接近两端，第二次叫完后从另一方向回看用户。
- 脖子：两次都让IO17到0°附近，但吸气、保持和离开路径不同；IO16在两次叫声之间大幅跨中位。
- 尾巴：第一次叫声先上提，巡视后才完成左右换边；第二次叫声使用另一高度，不长期锁在最高位。
- 亮点：适合有两段声峰或停顿的叫声，听起来像幼龙在等待并回应主人。

## 7. 低头进食 `DINO_ACTION_EAT`

适用：咀嚼音频、喂食配件、NFC食物、用户把食物送到嘴前。

只有IO17大于约135°、头部真正靠近食物时才会叠加咀嚼点头。长咀嚼音频会在四套片段间洗牌续演，一轮内每套各出现一次。

### 7.1 连续低头咬食 `eat-peck`

- 主体时长：约2.77秒。
- 故事：看见食物后连续吃三口，每次只抬起一点咀嚼，最后仍留在食物附近。
- 头部：轻微转脸寻找食物，并在低位配合点头咀嚼。
- 脖子：三次咬下分别到约178°、180°、176°；两口之间只抬到147°～151°。
- 尾巴：慢速满足摆动、高位保持或反向配重，不抢进食主体。
- 亮点：每次真正咬下都会把脖子压到接近最下方。

### 7.2 闻一闻再吃 `eat-sniff`

- 主体时长：约3.01秒。
- 故事：逐渐靠近闻两次，确认后深咬，再换到另一侧继续吃。
- 头部：两次嗅闻角度不同，咀嚼时轻微转脸。
- 脖子：先在126°～151°范围闻食物，再到180°深咬；之后跨过90°换边并到177°再咬。
- 尾巴：主要上提配重，左右幅度低于开心动作。
- 亮点：有“试探—确认—进食”的行为逻辑，不是直接重复点头。

### 7.3 吃到一半抬头看人 `eat-look-up`

- 主体时长：约2.58秒。
- 故事：先急着吃两口，突然完整抬头看用户，像在说“真好吃”，然后继续吃。
- 头部：抬起时回到90°正面对视约420毫秒。
- 脖子：开始即到180°咬食，中途完整抬到约84°、78°，之后再次下探到180°。
- 尾巴：抬头看用户时适当放低，重新吃东西时再次上提。
- 亮点：四套进食动作中互动感最强。

### 7.4 低位横向取食 `eat-low-graze`

- 主体时长：约3.50秒。
- 故事：先在地面一侧找到食物，低头吃下后保持脖子在低位，从中央一路吃到另一侧，最后满足地咀嚼。
- 头部：IO15总是比长颈先指向下一处食物，并在低位经过约8°、90°和172°，不是只上下点头。
- 脖子：IO17多次到176°～180°；保持低位时IO16从约166°经过90°到24°，实现左右移动着吃。
- 尾巴：随取食位置反向配重，脖子越低尾巴越上提；IO18在同一片段内跨过90°，IO8高度持续变化。
- 亮点：最符合“脖子弯到最下面以后左右找食物并扭头咀嚼”的实机表现。

## 8. 听声定位 `DINO_ACTION_LISTEN`

适用：脚步声、敲门声、用户从侧面说话、方向性声音输入。

### 8.1 冻结并定位 `listen-locate`

- 主体时长：约2.32秒。
- 故事：尾巴先绷住，头部定位第一方向，停下来听，再检查另一侧。
- 头部：快速到约128°，保持聆听后越过90°检查相反方向。
- 脖子：头部定位以后才跟随，随后慢慢恢复高位警觉。
- 尾巴：最先抬到约42°，左右只做较小确认。
- 亮点：用有意义的冻结表现“正在听”，而不是一直运动。

### 8.2 持续追踪 `listen-track`

- 主体时长：约2.29秒。
- 故事：听到移动的声源，持续追踪一侧，声音靠近后再转向另一侧。
- 头部：90毫秒内先到约142°，之后多次小范围重新定位。
- 脖子：抬高并在第一方向保持约420毫秒，再跨中位追踪声源。
- 尾巴：上提到约26°，大多位于头颈反方向。
- 亮点：比普通定位有更强的连续追踪感。

### 8.3 快速二次确认 `listen-double-check`

- 主体时长：约2.14秒。
- 故事：先后缩确认一侧，突然觉得不对，快速检查相反方向。
- 头部：第一侧停顿后快速跨越90°，形成明确的第二次确认。
- 脖子：IO17先回收到约62°，之后IO16从约138°跨到约52°。
- 尾巴：与头颈反向跨中位，随后慢慢恢复。
- 亮点：短而有戏剧性，适合脚步声突然变近。

### 8.4 高空声源定位 `listen-overhead`

- 主体时长：约2.83秒。
- 故事：小头先扫到极侧，长颈随后仰向天空倾听；声源越过头顶后，整条脖子和尾巴延迟追过去确认。
- 头部：IO15先接近4°，声源跨越后再接近176°，最后从另一边检查。
- 脖子：IO17到0°仰天倾听；IO16之后从约48°走到172°，再到另一端约12°。
- 尾巴：前半段刻意保持中位，确认声源移动后才大幅跨中位进行配重。
- 亮点：与水平脚步定位明显不同，展示顶部声源和仰天听声能力。

## 9. 受惊恢复 `DINO_ACTION_STARTLED`

适用：突然巨响、敲击、快速靠近、碰撞或错误反馈。正常待机不频繁触发。

### 9.1 后缩警戒 `startled-recoil`

- 主体时长：约2.88秒。
- 故事：先僵住，缩回长颈并高举尾巴，确认危险后谨慎靠近。
- 头部：冻结后先探出去检查，颈部稍后跟随。
- 脖子：IO17快速回收到约42°，保持判断后跨过中位检查两侧，最终前探到约108°。
- 尾巴：内部TUD上提到约22°～24°（实机IO8约156°～158°），IO18向反方向绷住。
- 亮点：具有恐龙式长颈回缩和高位尾巴守备姿态。

### 9.2 斜向避让 `startled-jump`

- 主体时长：约2.78秒。
- 故事：受到更强刺激后斜向躲开，尾巴反向甩出，再鼓起勇气回来。
- 头部：与长颈不同方向快速确认危险位置。
- 脖子：IO17回收到约30°，IO16偏到约140°；之后进行大范围两侧核查。
- 尾巴：先上提到约16°～20°，左右向头颈相反方向展开。
- 亮点：冲击强但不是连续抖动，只有一次避让和一次恢复。

### 9.3 低伏躲避 `startled-low-duck`

- 主体时长：约3.09秒。
- 故事：没有向上缩颈，而是整条脖子瞬间压到地面附近躲开；小头先探出确认，再重新昂首观察。
- 头部：低伏时接近IO15一端，随后先于脖子转到另一端检查危险。
- 脖子：IO17快速到180°最低位并冻结，再经中位抬到约24°高位验证安全。
- 尾巴：先高举并向一侧绷紧，颈部恢复后才跨到另一侧，最后回到90°。
- 亮点：与两套向上后缩动作形成第三种完全不同的惊吓轮廓。

## 10. 困倦入睡 `DINO_ACTION_SLEEPY`

适用：长时间无互动、入睡音频、低电量柔和提示、夜间模式。

### 10.1 长颈低位侧靠 `sleepy-neck-rest`

- 主体时长：约5.19秒。
- 故事：长颈逐渐失去力气，向前下方和侧面靠下，用慢呼吸进入休息。
- 头部：只做很小的跟随，避免警觉式快速观察。
- 脖子：IO17从108°缓慢下到146°、158°，最终保持150°～162°低位；IO16慢慢跨中位侧靠。
- 尾巴：内部TUD下沉到约112°～124°，仍受TUD最大125保护，对应实机IO8不低于55°。
- 亮点：每段持续720～1050毫秒，动作舒缓而不是突然倒下。

### 10.2 两次点头入睡 `sleepy-long-neck-nod`

- 主体时长：约4.62秒。
- 故事：第一次低头后突然醒一下，第二次点得更深，最后换一侧睡着。
- 头部：第一次低下后快速回正一点，第二次再慢慢失去注意力。
- 脖子：第一次到约156°，突然抬到118°；第二次下探到约172°，最后保持约152°。
- 尾巴：随困意缓慢下沉和换边，不做快速摇尾。
- 亮点：两次点头幅度和节奏不同，有明确的“困—醒—睡着”故事。

### 10.3 绕身寻找睡姿 `sleepy-neck-wrap`

- 主体时长：约5.90秒。
- 故事：长颈保持低位沿身体一侧缓慢放下，中途半醒一次，再跨过正面绕到另一侧寻找更舒服的位置。
- 头部：在低位随脖子反向补偿，中途只做一次回正半醒，不连续点头。
- 脖子：IO17在约162°～178°低位停留；IO16从约174°缓慢跨到18°，完整展示低位侧绕。
- 尾巴：比脖子晚约1.7秒才明显放松，左右经过两侧后回90°，上下也只缓慢下沉。
- 亮点：近6秒内没有短周期复读，适合入睡声和长时间陪伴展示。

## 11. 长环境音的5种自然场景

适用：下雨、森林、自然氛围等12～48秒环境音。同一场景不能连续出现，每次场景都会重新随机左右方向、头部相位和尾巴相位。

### 11.1 地平线巡视 `horizon-scan`

- 时长：6.8～9.5秒。
- 长颈从一侧完整跨过90°到另一侧。
- 头部先看远端，长颈稍后跟随。
- 尾巴在动作约30%以后才开始反向配重；IO18完整跨过90°，IO8同时走不同相位的高低弧。
- 头部微动作周期约5.7秒，尾巴微动作周期约7.9秒，且相位独立。

### 11.2 听雨 `rain-listen`

- 时长：4.2～6.5秒。
- 头部在动作4%～18%阶段先定位雨滴变化。
- 脖子约20%以后才开始跟随。
- 尾巴约43%以后才启动，在中高位沿一条大弧跨过左右两侧，而不是长期停在一边。
- 后段头部先解除凝视，身体再恢复，因此不会同步起停。

### 11.3 低头喝水 `low-drink`

- 时长：6.5～9秒。
- IO17从约108°下探到约176°。
- 低位完成数次小幅点水。
- 头部在不同节拍上两次抬眼看用户。
- 尾巴在动作后段才上提，并以不同周期跨过左右中位，不与点水同步。

### 11.4 抬头看天 `look-up`

- 时长：5.2～7.6秒。
- IO17从约164°低位大幅抬到约42°。
- 长颈抬稳以后，头部才转向天空一侧搜索。
- 尾巴只在动作54%～98%阶段完成一次上下左右空间圆，圆心不在IO8最高极限。
- 结束时稍微放松，不机械回到完全竖直姿态。

### 11.5 甩去雨水 `rain-shake`

- 时长：3.5～4.8秒。
- 头部先完成短促衰减甩动。
- 脖子稍晚、幅度更小、频率更低。
- 尾巴在动作54%以后才完成一次大扫。
- 属于低概率惊喜场景，不会连续出现。

环境音片段切换使用约1.1秒平滑过渡；音频结束后再用约1.4秒回到平静待机。

## 12. 待机生命动作

待机约每2～5秒可能出现一次短动作，完成后完整回落。

| 动作 | 每轮出现 | 表现 |
| --- | ---: | --- |
| 突然观察 `LIFE_GLANCE` | 1次 | 头先看动静，脖子延迟跟随约42%幅度，尾巴反向微调 |
| 中低位摇尾 `LIFE_TAIL_BURST` | 1次 | 尾巴放低后围绕90°完成约两次不等幅摇动 |
| 嗅闻 `LIFE_SNIFF` | 1次 | IO17两次点头，头部偏向一侧，尾巴轻微反向回应 |
| 精神一振 `LIFE_PERK` | 1次 | 长颈与尾巴抬高，头部做不同幅度的视线补偿 |

## 13. 基础待机姿态

| 姿态 | 主要表现 |
| --- | --- |
| 平静 | 90°附近小幅呼吸，尾巴左右慢摆 |
| 左侧好奇 | 长颈、头部和尾巴形成统一左侧观察姿态 |
| 右侧好奇 | 左侧好奇的镜像变化 |
| 活泼期待 | 脖子幅度较大，尾巴可以大幅跨中位 |

普通待机姿态之间使用约1.4秒平滑切换。

## 14. 随机表演叠加层

### 14.1 脖子风格

| 风格 | 表现 |
| --- | --- |
| `NECK_AUTHORED` | 保留动作原始关键帧 |
| `NECK_WIDE_ARC` | 叠加一次宽阔侧向巡视弧线 |
| `NECK_ORBIT` | 两路脖子形成空间椭圆 |
| `NECK_S_CURVE` | 叠加慢速S形柔性变化 |
| `NECK_REACH` | 加强面向用户或食物的前探 |

### 14.2 头部风格

| 风格 | 表现 |
| --- | --- |
| `HEAD_AUTHORED` | 保留编舞视线 |
| `HEAD_TRACK_NECK` | 反向补偿脖子，稳定观察目标 |
| `HEAD_USER_FOCUS` | 主要保持90°看正前方用户 |
| `HEAD_SIDE_GLANCE` | 单侧凝视后慢慢回正 |

### 14.3 尾巴风格

| 风格 | 表现 |
| --- | --- |
| `TAIL_AUTHORED` | 保留动作中的情绪轨迹 |
| `TAIL_CROSS_SWEEP` | 跨过90°中位完成宽扫 |
| `TAIL_CIRCLE` | IO8与IO18相差约四分之一相位画空间圆 |
| `TAIL_SIDE_FLICK` | 偏一侧短促轻甩 |
| `TAIL_COUNTERWEIGHT` | 与长颈方向相反进行动态配重 |
| `TAIL_HIGH_HOLD` | IO8在中高位完成蓄力、上翘、呼吸和回落，IO18独立轻摆 |
| `TAIL_LOW_SWEEP` | IO8先放到中低位，IO18再跨90°左右宽摆；摆动期间高度仍缓慢变化 |

系统会限制同一种风格连续重复，并根据尾巴最近实际左右停留时间修正下一次方向，避免长期偏左或偏右。宽扫和画圆至少完成约1.08圈相位，中低位摆动也保证在同一动作里跨过90°；最高位策略的权重已经降低，只有关键冲击瞬间短暂接近IO8=180°，不会每段都把尾巴举着。

V3.2进一步修正实机“看不到尾巴向下”的问题：

- 平静待机的内部TUD中心从82调整为104，对应实机IO8约76°，默认即可看见中低位尾巴；
- 好奇待机中心对应实机IO8约88°，活泼待机约104°，自信姿态约120°，困倦约62°，形成高、中、低完整层次；
- `TAIL_LOW_SWEEP`在撒娇、进食、听声、困倦和发现中的权重明显提高，并加强到86%轨迹混合，低位不会被原高位关键帧淹没；
- 宽扫中心下移到内部TUD约72，空间圆中心下移到约76，因此左右运动本身就会经过更明显的高低区间；
- 全局“脖子下探就抬尾”的配重系数从0.18降到0.10，进食仍保留关键帧抬尾，但不会所有动作都被配重规则拉到高位；
- 待机摇尾改为中低位左右摇；“精神一振”仍然抬尾，所以日常观察中会同时看到向下摇和突然上提。

这里不是把尾巴统一改成下垂：高位展示、中位配重、低位左右摆、跨中位宽扫、空间圆、侧甩和原编舞全部保留，只按不同情绪调整出现概率。

### 14.4 动作内部随机层

V3.1不仅在动作开始时随机选择片段和风格，还会改变同一个片段内部的过程：

- 每个关键帧根据本次动作随机种子获得86%～116%的独立时长，停顿、靠近和回望不再保持固定比例；
- 头部可在随机时刻出现一次可选回看，时间、方向、幅度和持续宽度每次不同；
- 脖子可在另一随机时刻出现一次犹豫、再靠近或侧向确认，上下与左右幅度分别随机；
- 尾巴拥有独立的随机补摆和高度变化，发生时间不与头部、脖子或音频声峰强制同步；
- 某些小反应本次会被省略，下次才出现，因此不是给固定关键帧简单增加同一套装饰；
- 每个随机事件使用单次余弦脉冲连续进入和退出，不会产生随机角度跳变或快速机械抖动。

待机生命动作也采用受控随机：观察、摇尾、嗅闻和精神一振使用随机洗牌袋，四种全部出现一次之前不会重复；左右方向仍然随机，只有第三次仍同向时才校正，因此不会呈现机械的左—右—左—右顺序。

### 14.5 V3.3多层防复读

“永远不重复”在有限动作库中不可能，但系统会把可察觉的重复间隔尽量拉长，并保证再次出现时不是原样播放：

| 层级 | 防复读规则 |
| --- | --- |
| 同一情绪动作片段 | 3～4个片段随机洗牌；本轮全部演完前不重复 |
| 洗牌轮次边界 | 下一轮第一个片段不能等于刚完成的最后一个片段 |
| 完整表演组合 | 记忆最近12次“情绪＋片段＋镜像方向＋脖子风格＋头部风格＋尾巴风格”；撞到则重新抽取 |
| 动作内部过程 | 每次重新生成关键帧节奏、头部回看、脖子犹豫、尾巴补摆与高度变化 |
| 实时声音层 | PCM音量、起音和停顿不同，同一片段的头颈细节也随声音实时变化 |
| 长环境音 | 5个自然场景全部出现一次后才重新洗牌，并阻止跨轮立即重复 |
| 待机生命动作 | 4种动作全部出现一次后才重新洗牌，并阻止跨轮立即重复 |

洗牌不是固定顺序：每轮都重新执行Fisher-Yates随机排列，因此客户不会看到固定的A→B→C→D循环。串口动作日志输出 `sig`，可用于检查近期完整表演组合是否发生碰撞。

## 15. 音频自动对应规则

| 文件名或时长特征 | 自动选择动作 |
| --- | --- |
| 包含“咀嚼”、`eat`、`chew` | 进食 |
| 包含“脚步”、`step`、`foot` | 听声定位 |
| 包含“入睡”、`sleep` | 困倦 |
| 包含“警觉”、`startle` | 受惊 |
| 包含“雀跃”、`happy`、`joy` | 开心 |
| 包含“亲近”、`comfort`、`nuzzle` | 亲近 |
| 普通叫声不超过1.5秒 | 发现 |
| 普通叫声1.5～2.7秒 | 开心 |
| 普通叫声超过2.7秒 | 威风鸣叫 |
| `ambient`分类长音频 | 五种自然场景随机续演 |

当前 `audio_serverWeb/audio_files/dinosaur` 实际素材对应关系：

- 叫声约1.017秒：发现用户；
- 叫声约1.995～2.563秒：开心回应；
- 叫声约3.004～6.909秒：威风鸣叫；
- 咀嚼约3.130、5.756和12.006秒：四种进食动作，长音频自动换不同片段；
- 脚步约1.832和11.841秒：四种听声动作，长音频自动换不同片段；
- 环境音约12.006～48.007秒：五种一次性自然场景随机切换，不连续重复。

文件名和总时长先决定“演什么”，解码后的PCM再决定“这一刻演多强”。音频模块每约5毫秒更新一组 `AudioMotionData`：

- `level`：平滑音量包络。长啸越响，IO17越向0°仰起；亲近声越持续，长颈靠近感越明显；
- `attack`：新声峰强度。用于检测一次叫声起音、一口咀嚼或一步脚步，触发短暂提颈/点嚼/警觉；
- `elapsed_ms` 与 `duration_ms`：让长叫声中段保持更宽的姿态，音频后段逐渐收势；
- `sound_index`：保留按某个具体文件进一步精调的接口。

各情绪的实时声音对应如下：

| 动作 | PCM驱动部位 | 实时效果 |
| --- | --- | --- |
| 发现 | IO17、IO15 | 短叫起音提颈，小头随声峰确认 |
| 亲近 | IO17、IO16 | 持续柔声加深靠近，起音时轻抬头看主人 |
| 开心 | IO17、IO16 | 每个兴奋起音增加昂首，持续段轻微侧移 |
| 长啸 | IO17为主，IO16/IO15辅助 | 音量与起音共同驱动仰天幅度，总时长控制长叫中段展开 |
| 进食 | IO17、IO16、IO15 | 一口声音触发低位点嚼，持续咀嚼驱动脖子左右找食物和反向扭头 |
| 听声 | IO17、IO16、IO15 | 脚步起音触发警觉，持续段慢慢定位方向 |
| 受惊 | IO17 | 突然声峰产生一次回缩，不连续发抖 |
| 困倦 | IO17 | 持续低声只增加很小的下沉呼吸 |

尾巴不直接逐帧跟随PCM音量。它根据动作情绪、长颈配重和独立延迟轨迹运动，避免所有舵机随着同一个声音包络同步跳动。

## 16. 调用接口

只触发动作：

```cpp
TriggerDinoAction(DINO_ACTION_DISCOVER);
TriggerDinoAction(DINO_ACTION_AFFECTION);
TriggerDinoAction(DINO_ACTION_HAPPY);
TriggerDinoAction(DINO_ACTION_PROUD_CALL);
TriggerDinoAction(DINO_ACTION_EAT);
TriggerDinoAction(DINO_ACTION_LISTEN);
TriggerDinoAction(DINO_ACTION_STARTLED);
TriggerDinoAction(DINO_ACTION_SLEEPY);
```

自动选择匹配音频并触发：

```cpp
TriggerDinoActionWithAutoSound(DINO_ACTION_HAPPY);
```

根据指定Flash音频自动判断动作：

```cpp
TriggerDinoSoundAction(sound_index);
```

开机选择短叫声并问候：

```cpp
TriggerDinoGreeting();
```

接口只把请求放入动作队列，不阻塞业务线程。动作任务以50 FPS输出五路舵机姿态。
