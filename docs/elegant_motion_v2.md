# 恐龙萌宠优雅动作 V3.3：新老动作对比与调用说明

本文说明 `auto_run.cc` 新动作系统相对旧系统的变化、八种萌宠动作的表现设计，以及传感器、语音和 Web 控制代码如何调用动作。

## 1. 硬件部位基准

所有动作严格使用工程中的五路实际舵机定义：

| 索引 | GPIO | 部位 | 角度方向 |
| --- | --- | --- | --- |
| 0 | IO17 | 脖子上下 | 0°最上/仰天，90°中位，180°最下/进食 |
| 1 | IO16 | 脖子左右倾 | 0°右倾，90°中位，180°左倾 |
| 2 | IO15 | 头部左右转 | 0°最右，90°朝前，180°最左 |
| 3 | IO8 | 尾巴上下 | 55°最下安全位，90°中位，180°最上 |
| 4 | IO18 | 尾巴左右 | 0°最左，90°中位，180°最右 |

平静默认姿态把IO17设为70°，比几何中位抬高20°；上电、自动任务初始值和Web默认滑块保持一致。动作中的90°仍表示机械中位，不改变各轴方向定义。

头部舵机不能让头倾斜。动作中的“好奇歪头”由IO16脖子左右倾实现，IO15头部舵机进行反向小幅补偿，使恐龙歪着脖子仍然看向用户。

头部与尾巴左右轴的逻辑中位都保持 **90°**：头部90°朝正前方，尾巴90°位于左右中央。V2.2不会修改机械中位，而是在编舞层解决尾巴偏左和头部停边问题。

## 2. 新老系统总体对比

| 对比项 | 旧动作系统 | V2 动作系统 |
| --- | --- | --- |
| 动作组织 | 脖子、头部、尾巴分别随机选模式 | 一个高层动作统一编排五路舵机 |
| 动作形式 | 正弦波周期运动 | 连续曲线关键帧 + 有机待机波形 + 非同步微动作 |
| 部位顺序 | 五路基本同时变化 | 头先注意、脖子跟随、尾巴最后表达情绪 |
| 音频匹配 | 根据 TOC 数字索引 `1/2/3/4` 判断 | 根据文件名语义和音频时长判断 |
| 文件变化 | 服务端增删文件后索引可能错位 | 文件顺序变化不影响动作类型 |
| 情绪一致性 | 可能出现脖子看左、头看右、尾巴警觉的冲突组合 | 每个行为预设统一控制姿态和情绪 |
| 动作衔接 | 固定3秒模式交叉渐变 | 先看用户260ms，按情绪慢收势0.8～1.9秒，再回到有生命感待机 |
| 左右变化 | 大多固定方向 | 随机选择跨中位、单侧凝视、画圆、S形、配重等策略，并限制连续重复 |
| 同类动作 | 每个情绪只有一种固定表现 | 8种情绪共29个动作片段，每次选择不同变体、速度和力度 |
| 音频利用 | 只判断是否正在播放 | 文件名决定情绪、总时长决定短叫/长叫；解码PCM实时提取音量、起音和播放进度驱动脖子 |
| 长音频 | 一个周期模式一直摆动或动作提前结束 | 叫声/进食/听声换不同片段续演；环境音在五种一次性自然场景间随机切换 |
| 软件范围 | 最终只限制在0°～180° | 头部、脖子、尾巴左右0°～180°；IO8尾巴上下55°～180° |
| 外部调用 | 需要调用方理解 Neck/Head/Tail 模式 | 调用方只需请求“开心”“撒娇”等角色动作 |
| 调试方式 | Web主要依靠五个角度滑块 | Web增加八个动作试演按钮 |

## 2.1 V2.1实机反馈优化

V2首次实机测试发现逐段 `smoothstep` 会让舵机在每个关键帧到达时速度归零，视觉上形成“走一下、停一下”。V2.1进行了以下调整：

- 普通动作段改用Catmull-Rom连续曲线穿过关键姿态，不在每个姿态机械刹停；
- 只有“听见声音后的冻结”“受惊判断”等有表演意义的停顿仍然保留；
- 每次动作随机产生92%～116%的速度变化；
- 高冲击动作随机使用约1.22～1.36倍表现力度；
- 动作过程中叠加不同周期的头、脖子和尾巴微动作，五路舵机不再同频同步；
- 表演软件范围扩大到接近全行程，但保留约10°～15°端点余量；
- 每种情绪至少两套完整编舞，进食和听声各有三套；
- 长音频播放期间只允许切换到不同片段，不允许重复刚刚完成的动作。

## 2.2 V2.2实机反馈优化

V2.2针对“头部扫到两端后停在左侧、尾巴动作偏左、长音频几乎不动、脖子和尾巴轨迹单调”继续优化：

- IO15头部早期版本使用30°～150°观察区；V2.9按实机能力开放0°～180°；
- 头部每段动作结束先保留短暂凝视，再用0.8～1.9秒的随机情绪收势柔和回到90°正前；尾巴左右轴同时回到90°中位；
- V2.2曾用左右严格交替解决连续偏向；V2.3起改为随机方向并只限制连续三次同向，避免形成新的固定规律；
- IO17和IO16两路脖子按实机能力开放0°～180°全行程；
- 开心与威风鸣叫各增加一套空间大圆动作，两路脖子和两路尾巴采用相位差画椭圆；
- 约6.9秒的长叫声会在三套不同鸣叫表演间换段续演，不再3秒后回到小幅待机；
- 12～48秒环境音使用慢速大幅双圆场景：脖子约8.4秒一圈、尾巴约6.7秒一圈，半径还会缓慢改变；
- 待机加入四种一次性“生命脉冲”：突然观察、短促摇尾、两次嗅闻、精神一振；每次做完就回落，不无限重复；
- 所有互动动作增加260ms正面注意前奏：先看向正前方用户，再执行撒娇、进食、鸣叫等回应。

## 2.3 V2.3尾巴仿生优化

V2.3不再把“镜像”理解成一次动作只能摆一边，也没有规定每个动作都必须完整扫过左右两侧。动作启动时会按情绪随机选择尾巴策略：保留编舞、跨中位宽扫、上下左右画圆、单侧轻甩、头颈反向配重、高位上翘保持。同一种策略最多短暂重复，不会长期复制粘贴。

不同情绪使用不同尾巴节奏：

- 开心更容易随机到大幅宽扫或空间画圆，也可能只做一串俏皮轻甩；
- 撒娇更容易使用单侧轻甩、柔和宽扫或慢圆；
- 威风鸣叫偏向空间画圆和动态配重；
- 进食偏向保留编舞、单侧满足轻甩和配重，偶尔才大扫；
- 听声和受惊偏向绷紧、单侧确认或反向配重；
- 困倦偏向原编舞和很慢的小幅动作，不强制左右换边。

IO8尾巴上下轴按最终实机关系限制为55°～180°：55°是最下安全位，180°是最高位。自主动作、Web手动控制和其他业务代码调用 `SetServoAngle()` 都受同一保护。脖子向下探时尾巴相应上提，模拟动态配重。

动作参考依据：Cats Protection的[猫身体语言与尾巴表达](https://www.cats.org.uk/help-and-advice/cat-behaviour/cat-body-language)强调要结合情境理解高位、摆动和紧张尾姿；恐龙运动模拟研究显示尾巴会参与全身角动量调节和动态平衡，可参见[Royal Veterinary College研究说明](https://www.rvc.ac.uk/research/research-centres-and-facilities/structure-and-motion/news/computer-simulations-reveal-dinosaurs-wagged-their-tails-when-running)及[三维运动模拟论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC8457660/)。本产品据此采用“情绪表达 + 头颈反向配重”，而不是把尾巴当作独立雨刷器。

## 2.4 V2.4全身随机表演系统

随机性扩展到脖子、头部和尾巴三个层级，而不只是随机换一个固定动作文件：

- 脖子随机选择原编舞、宽阔单次弧线、二维空间椭圆、慢速S形、面向用户前探；
- 头部随机选择原视线、反向补偿脖子、保持90°看用户、单侧凝视后慢回正；
- 尾巴随机选择五种情绪策略，并拥有独立的幅度、周期和首次方向；
- 动作片段、镜像方向、速度、力度、脖子风格、头部风格和尾巴风格共同组合；
- 同一种头部、脖子或尾巴风格连续出现时会重新抽取，避免形成可预测模板；
- 头颈主动作整体降速，开心舞动改为少量宽弧线，快速反向只保留给发现、受惊和真正咬食；尾巴仍允许快速摇动。

产品的核心创新表现是：IO17与IO16驱动柔性长脖子在0°～180°二维范围内画空间轨迹，IO15同时独立补偿视线，让恐龙可以“身体绕着观察、头却仍看着用户”；两路尾巴再做情绪表达或动态配重。这比普通单轴摇头/摆尾玩具更接近角色动画中的全身表演。

## 2.5 V2.5尾巴方向记忆与高位尾姿

实机观察发现，简单统计“向左动作一次、向右动作一次”仍会产生视觉偏差：左侧慢弧可能持续数秒，而右侧轻甩只有几百毫秒。V2.5改为以50FPS记录实际输出角度相对90°中位的“角度×时间”指数记忆：

- 正值表示IO18最近在右侧（大于90°）停留更多，后续向左首摆概率逐渐提高；
- 负值表示IO18最近在左侧（小于90°）停留更多，后续向右概率提高；
- 修正概率限制在18%～82%，因此仍保留随机性，不会变成强制交替；
- 中位待机期间记忆自然衰减，不会永久带着历史偏差；
- 串口动作日志增加 `tail_bias`，方便实机判断最近究竟偏向哪侧。

同时新增 `TAIL_HIGH_HOLD` 高位尾姿。IO8在较高区域缓慢蓄力、上翘和回落，IO18左右轴独立轻摆；开心、威风和听声动作更容易抽到这一姿态。V3.0不再把IO8长时间顶在180°，只有长啸冲击、受惊定格等瞬间接近最高位。

## 2.6 V2.6受控随机与下垂限制

灵动性来自“受控随机”，而不是五路舵机各自抽取无关角度。每次表演会随机组合动作片段、镜像方向、速度、力度、脖子风格、头部视线和尾巴风格，但所有选择都受当前情绪约束，并带有防连续重复和左右时间记忆。这样同一个“开心”可能表现为画圆、宽弧或前探，却仍然一直像开心。

IO8物理输出严格限制在55°～180°：55°是最低安全位，180°是最高位。编舞内部使用反向TUD（0最高、125最低），因此任何随机叠加、空间圆和曲线插值最终都不会越过向下安全限制。

当前动作变体数量：

| 情绪 | 变体 |
| --- | --- |
| 发现用户 | 直接发现、胆怯偷看、仰望追踪 |
| 亲近撒娇 | 长颈低头问候、侧面缓慢靠近、脸颊轻蹭、害羞低头贴近 |
| 开心 | 幼龙昂首展示、长颈跨身宽扫、全行程空间画圆、追尾游戏 |
| 威风鸣叫 | 正面蓄力、斜向大幅巡视、长音频慢速大圆、双段仰天回应 |
| 进食 | 连续啄食、闻后咬食、抬头确认、低位横向取食 |
| 听声 | 定位声源、持续追踪、快速二次确认、高空声源定位 |
| 受惊 | S形后缩、斜向避让、低伏躲避 |
| 困倦 | 长颈低位侧靠、两次点头入睡、绕身寻找睡姿 |

## 2.7 V2.7“幼年长颈恐龙萌宠”动作语言

V2.7把角色从“会摇头摆尾的通用宠物”进一步定义为**幼年长颈恐龙萌宠**。这是一套产品角色设计，不声称复原某一个确定物种；依据是本产品长颈、长尾、四足躯干的机械外形，并综合长颈蜥脚类的取食与头颈力学研究。

新的表演原则是“长颈恐龙为骨架，猫狗萌宠为情绪点缀”：

- **小头先发现，长颈后跟随**：头部短促确认目标，随后两路柔性脖子跨过90°中位做大范围巡视；头部再反向补偿，使视线仍然锁定用户。
- **脖子负责空间到达**：发现、开心和鸣叫采用昂首警戒、宽阔侧扫与前探；进食在低位/中位取食边界移动，而不是原地上下啄同一点。
- **尾巴兼顾配重与表达**：警戒、巡视和进食以反向配重、高位保持为主；开心和亲近仍可随机出现快速跨中位摇尾、空间画圆和单侧轻甩，保留萌宠吸引力。
- **亲近有四种性格**：长颈低头、侧面缓慢靠近、猫式脸颊轻蹭和害羞低头贴近随机混用，因此既像恐龙，也会偶尔给人熟悉的宠物惊喜。
- **受惊不再固定夹尾**：恐龙式版本让脖子后缩、尾巴高举并反向绷住，短暂停顿后小头先探、整条脖子再核查；其他情绪中仍允许放松下垂尾姿。
- **困倦按长颈结构下沉**：IO17逐渐走到约150°～172°，IO16形成大范围侧靠；尾巴只轻度下沉，实机IO8仍受55°最低安全位保护。
- **长环境音使用自然场景状态机**：地平线巡视、听雨、低头喝水、抬头看天、偶发甩水各自只演一次，随后随机换到不同场景；头、颈和尾巴拥有不同延迟、周期和相位。

设计依据与边界：美国自然历史博物馆对蜥脚类长颈的说明指出，长颈可扩大不移动身体时的取食范围；Mamenchisaurus头颈力学研究支持低/中位取食，颈部前端完成较快的小范围头部调整，而整条颈部负责较慢的大范围定位。尾巴三维动力学研究显示尾巴会参与全身动态运动，因此本产品把它设计为头颈的可见反向配重。这些研究用于提取可信的动作语法，不代表玩具动作是严格古生物复原。

- [AMNH：Sauropod Biomechanics — Who Needs Necks?](https://www.amnh.org/exhibitions/dinosaurs-ancient-fossils/sauropod-biomechanics/who-needs-necks)
- [Mamenchisaurus youngi neck posture and mobility](https://pmc.ncbi.nlm.nih.gov/articles/PMC3812961/)
- [Dynamic musculoskeletal simulation of dinosaur tail motion](https://pmc.ncbi.nlm.nih.gov/articles/PMC8457660/)
- [Sauropod neck posture and feeding mechanics](https://pmc.ncbi.nlm.nih.gov/articles/PMC3812989/)

## 2.8 V2.8长环境音去循环与去同步

V2.7环境音虽然让脖子、头和尾巴使用不同周期，但本质仍是一组连续数学波形。长时间观看后仍能识别出同一动作族循环，而且头部补偿与尾巴配重的关联过强，看起来像同步机构。V2.8改为五种有起点、有过程、有结束的一次性场景：

| 场景 | 时长 | 动作叙事 | 部位时序 |
| --- | --- | --- | --- |
| 地平线巡视 | 6.8～9.5秒 | 昂首从一侧完整看到另一侧 | 头先看远端，长颈随后横跨，尾巴最后反向配重 |
| 听雨 | 4.2～6.5秒 | 突然听见雨滴变化并安静确认 | 头约0.2秒内定位，颈部约0.5秒跟随，尾巴约1秒后绷起 |
| 低头喝水 | 6.5～9秒 | 长颈下探、点水、途中两次抬眼看用户 | 点水节拍、头部抬眼和尾巴上提互不共相位 |
| 抬头看天 | 5.2～7.6秒 | 从低位大幅抬头观察天空 | 颈部先抬稳，头部随后搜索，尾巴仅在后段单扫一次 |
| 甩去雨水 | 3.5～4.8秒 | 偶发的快速甩水惊喜 | 头部先短促甩动，颈部较慢跟随，尾巴在动作后半段才扫动 |

调度规则：同一场景不能连续出现；左右方向随机，但连续两段同向后会强制换边；每次进入场景随机生成独立头部相位和尾巴相位；切换使用约1.1秒连续过渡，环境音结束后再用1.4秒回到平静待机。这样30～48秒下雨音频会形成一段不可预测的小故事，而不是把同一条轨迹播放四遍。

## 2.9 V2.9按实机重新确认舵机对应关系

V2.9不再沿用早期样机部位假设，所有底层GPIO、Web滑块、动作关键帧和文档统一采用本次实机关系：IO15头部左右、IO16脖子左右、IO17脖子上下、IO8尾巴上下、IO18尾巴左右。

- 威风鸣叫的四套动作都会把IO17抬到0°附近并保持，形成真正的仰天长啸；
- 四套进食动作继续让IO17到达约176°～180°，形成真正低头吃东西；
- IO8硬件输出限制为55°～180°，55°是最下安全位、180°是最高位；
- IO18以90°为左右中位，0°最左、180°最右；
- 尾巴方向记忆按实际输出的“角度×时间”计算，并同时修正下一段镜像概率和当前轻微漂移，避免长期偏左；
- IO15头部开放0°～180°，发现、听声和受惊动作可随机使用更大的独立视线幅度。

## 2.10 V3.0动作多样性、立体尾姿与实时声音驱动

V3.0把互动动作从21套扩充为29套：八种情绪各增加一条与原动作明显不同的完整行为路线。新增仰望追踪、害羞低头贴近、追尾游戏、双段仰天回应、低位横向取食、高空声源定位、低伏躲避和绕身寻找睡姿。随机系统避免连续选择刚完成的片段，因此长音频换段不是原动作复读。

尾巴成为全身最醒目的情绪器官，但不等于一直上翘到极限：

- IO18宽扫必须在同一片段内跨过90°左右中位，IO8同时走高低椭圆；
- 空间圆让IO8与IO18相差约四分之一相位，使用两路尾巴自由度；
- 中低位摆动会先把IO8放到约66°～88°物理高度，再让IO18跨过90°左右慢扫；扫动时IO8仍继续改变高度；
- 高位尾姿在中高位经历蓄力、短暂上翘和回落，只有长啸冲击或受惊定格接近IO8=180°；
- 动态配重根据IO16方向和IO17下探程度改变左右与高度，进食时脖子越低，尾巴越上提；
- 最近真实左右停留面积继续反馈到镜像概率和轻微实时校正，既保持随机又不长期偏左。

声音对应也从“文件名+是否播放”升级为三级数据：

1. 文件名语义决定情绪：咀嚼、脚步、入睡、警觉、雀跃和亲近分别进入对应动作池；
2. 总时长区分短促发现、开心回应和长啸，并决定长音频是否换不同片段续演；
3. Opus解码后的PCM每约5毫秒提取平滑音量、起音强度和播放进度，实时驱动脖子细节。

长啸声峰使IO17进一步向0°仰天，咀嚼起音只在低位触发点嚼并让IO16横移、IO15反向扭头，脚步起音产生一次警觉提颈。尾巴不复制PCM波形，而是延迟表达情绪和身体平衡，从根本上避免头、颈、尾同拍同步。

## 2.11 V3.1从“随机选模板”到“模板内部也不同”

V3.0虽然拥有29个片段和多种头颈尾风格，但一个片段被选中后，各关键帧之间的时间比例仍然固定，多次观看仍可能认出动作模板。V3.1增加每次表演专属且保持连续的随机种子：

| 层级 | V3.0 | V3.1 |
| --- | --- | --- |
| 片段节奏 | 整段统一随机快慢 | 每个关键帧再独立使用86%～116%时长 |
| 头部细节 | 由选中的视线风格决定 | 随机时刻可选一次回看，也可能本次不出现 |
| 脖子细节 | 宽弧、空间圆等整段风格 | 另有独立时刻的犹豫、再靠近或侧向确认 |
| 尾巴细节 | 选择一种整段尾姿 | 随机时刻增加一次补摆及独立高度变化 |
| 待机方向 | 曾经严格左右交替 | 真随机，只阻止第三次连续同向 |
| 待机类型 | 可能连续抽中同一生命动作 | 允许自然重复一次，但阻止连续三次相同 |

这些随机量在一次动作开始时生成，动作采样过程中保持稳定，并通过单次平滑脉冲加入原编舞。因此随机性改变的是“什么时候犹豫、看哪里、尾巴何时补一下”，不会每20毫秒重新抽角度，也不会破坏进食、听声、撒娇或长啸的情绪语义。

## 2.12 V3.2高、中、低完整尾姿

V3.1虽然加入中低位摆动，但原关键帧大多把内部TUD写在0～60的高位区域，叠加进食配重后，低位随机样式在实机上仍不够明显。V3.2同时调整待机中心、随机权重、轨迹圆心和全局配重，而不是只添加一个偶尔抽中的低位动作。

| 尾姿 | 典型实机IO8 | IO18配合 | 主要情绪 |
| --- | --- | --- | --- |
| 瞬间高举 | 150°～180° | 绷紧、宽扫或缓慢跨中位 | 长啸高潮、开心展示、受惊定格 |
| 中高位配重 | 105°～150° | 与IO16长颈方向相反 | 进食、巡视、自信站立 |
| 中位自由弧 | 85°～115° | 左右宽扫并持续改变高度 | 开心、发现、亲近 |
| 中低位左右摆 | 60°～90° | 在同一动作内跨过90°左右中位 | 平静、撒娇、听声、吃完放松 |
| 最低安全位附近 | 55°～70° | 小幅慢摆或安静停留 | 困倦、休息、偶发放松 |

平静待机现在以IO8约76°为中心，尾巴不再默认翘着；待机摇尾会先放低再左右晃，而精神一振仍会突然抬高。所有姿态最终继续受IO8=55°～180°双层安全限制。

## 2.13 V3.3随机洗牌与近期表演记忆

V3.3把“避免连续重复一个动作”升级为完整防复读系统：

- 每种情绪自己的3～4个动作使用随机洗牌袋，本轮所有片段出现以前不能重复；
- 新一轮洗牌会检查上一轮最后片段，阻止轮次边界立即复读；
- 最近12次完整表演保存组合签名，签名包括情绪、片段、镜像方向和头、颈、尾三种表演风格；
- 如果新组合与近期签名相同，最多重新抽取6次风格与方向；
- 5种环境音场景和4种待机生命动作分别拥有自己的随机洗牌袋；
- 每轮排列重新随机，不形成固定轮播顺序。

当动作库最终不可避免地再次出现同一片段时，V3.1的帧内随机和实时PCM响应仍会生成不同节奏、不同局部反应与不同声音幅度，因此客户看到的是同一种情绪的另一种表演，而不是录像循环。

## 3. 旧动作系统存在的具体问题

### 3.1 独立随机导致表演不连贯

旧系统分别从 Neck、Head、Tail 三个数组随机选择模式。每个模式本身可以运动，但组合后未必属于同一种情绪。例如：

```text
脖子：LOOK_LEFT
头部：LOOK_RIGHT
尾巴：DROOP
```

用户很难判断它是在观察、害怕还是困倦。V2 使用完整行为预设，五路舵机共享一个情绪意图。

### 3.2 声音与动作只是同时开始

旧系统检测到音频播放后，仅切换到一个周期波形，动作没有“蓄力、冲击、停顿、回弹”等声音时间结构。

V2 的鸣叫动作会先后仰吸气，再在叫声开始阶段向前发力；短叫先转头发现用户，再歪脖并摇尾回应。

### 3.3 数字索引映射不稳定

服务端按照 `animal`、`ambient` 分类以及文件名字典序产生索引。旧代码把索引3固定当作咀嚼声，但当前服务端索引3实际仍可能是叫声。

V2 使用下列语义规则：

- 文件名包含“咀嚼”、`eat`、`chew`：进食动作；
- 文件名包含“脚步”、`step`、`foot`：听声定位动作；
- 文件名包含“警觉”、`startle`：受惊恢复动作；
- 文件名包含“雀跃”、`happy`、`joy`：雀跃开心动作；
- 文件名包含“亲近”、`comfort`、`nuzzle`：贴贴撒娇动作；
- 普通编号叫声：根据时长区分短促发现、开心回应和威风鸣叫。

## 4. V2 八种角色动作

### 4.1 发现你了 `DINO_ACTION_DISCOVER`

基础时长约1.95秒；另有“胆怯偷看”变体，实际速度会随机变化。

1. IO15头部在140ms内先转向一侧；
2. 停顿170ms，表现“确认看见”；
3. IO17先抬高整条颈部，IO8同时把尾巴举到高位警戒；
4. IO16让整条脖子从一侧跨过90°中位巡视到另一侧，IO15反向补偿视线；
5. 确认安全后向正前方用户做一次明显前探；
6. 回到仍然保持注意力的长颈警戒姿态，而不是机械回中。

适用：开机问候、检测到人脸、检测到唤醒词、短促疑问叫声。

### 4.2 长颈问候与贴贴 `DINO_ACTION_AFFECTION`

共有正面低头问候、侧面缓慢靠近、脸颊轻蹭和害羞低头贴近四种变体。

恐龙式变体会先以头部90°看用户，随后整条脖子前下探，把额头送到用户手边并安静停留；萌宠变体则从一侧送出脸颊，用一条连续大弧跨过90°完成轻蹭。尾巴可随机选择高位配重，也可开心地快速摇动，因此不会每次都像同一个模板。

适用：摸头、抱起、连续触摸、用户说“贴贴”。

### 4.3 雀跃开心 `DINO_ACTION_HAPPY`

共有幼龙昂首展示、长颈跨身宽扫、招牌空间轨迹和追尾游戏四种变体。

脖子先昂首形成长颈剪影，再用一条连续大弧跨过90°中位到达另一侧，最后向用户前探；尾巴始终较高，并随机选择反向配重、快速摇尾或空间圆。头部幅度小于长颈并负责视线补偿，使整体活泼但不会像五个舵机同步振荡。

适用：短叫回应、连续互动、识别到主人、完成任务后的奖励反馈。

### 4.4 威风鸣叫 `DINO_ACTION_PROUD_CALL`

基础时长约3.00秒；另有从斜侧蓄力、横跨大范围巡视的变体。

先后仰蓄力和短暂停顿，再快速前探鸣叫；尾巴高高翘起，随后头颈巡视左右两侧，最后保持自信姿态缓慢放松。

适用：较长恐龙叫声、产品展示、角色招牌动作。

### 4.5 低头进食 `DINO_ACTION_EAT`

共有四种不同片段：低头啄食、闻一闻再咬、吃到一半突然抬头确认、低位横向取食。咀嚼音频较长时使用洗牌袋接续，一轮内四种各出现一次，并阻止跨轮立即重复。

进食动作按“看用户手中的食物—靠近闻两下—IO17压到176°～180°咬下—保持低位咀嚼—IO16横向换食物点、IO15反向扭头定位”的顺序表演。只有靠近食物时才叠加咀嚼点头；实时PCM起音决定每一口的细节幅度。抬头确认片段会完整抬到约80°并以头部90°看用户一会儿；低位横向取食则让IO16从约166°跨过90°到24°，真正表现一边低头一边左右吃。

适用：所有咀嚼类音频、喂食配件或NFC食物互动。

### 4.6 听声定位 `DINO_ACTION_LISTEN`

共有定位、追踪、二次确认和高空声源定位四种片段。脚步音频未结束时切换到不同片段继续判断，不做原样循环。

先冻结并把尾巴立起，再由头部快速确定第一方向，脖子随后歪向声源；停顿倾听后检查另一侧，最后回到警觉中位。

产品没有腿部运动舵机，因此脚步声不再伪装成“自己走路”，而是表现成幼龙听到远处脚步并定位，更符合硬件能力。

### 4.7 受惊恢复 `DINO_ACTION_STARTLED`

时长约2.50秒。

先冻结80ms，然后脖子快速后缩、尾巴上提并向反方向绷住；停顿判断危险后，头部先探出去检查，整条脖子再跨过中位核查另一侧，最终谨慎靠近并恢复。

适用：突然大声、敲击、快速靠近或错误反馈。这个动作不应该频繁随机触发。

### 4.8 困倦入睡 `DINO_ACTION_SLEEPY`

时长约4.72秒。

脖子逐渐向前下方降低并形成宽阔侧靠，IO17可下探到约150°～172°；尾巴只轻度下沉，最后用两个非常慢的大幅点头和小幅呼吸进入休息。

适用：长时间无互动、睡眠音频、低电量柔和提示。

## 5. 有机待机系统

关键帧动作之外，V2保留持续的生命感，但不再随机拼装身体部位。待机使用七套完整姿态：

- 平静呼吸；
- 向左好奇；
- 向右好奇；
- 活泼期待；
- 自信站立；
- 困倦休息；
- 环境音自然场景。

各姿态仍使用非对称谐波波形，但五路舵机的中心、幅度和周期来自同一预设。姿态之间使用1.4秒平滑切换；关键帧表演按情绪使用0.8～1.9秒慢收势，保证头部与尾巴回中，再平滑进入待机。待机每隔约2～5秒随机出现一次观察、摇尾、嗅闻或精神一振；观察占40%，摇尾占25%，其余为嗅闻和昂首。动作结束后完整回落，因此有生机但不持续复读同一动作。

## 6. 动作调用接口

接口定义在 `main/auto_run.h`。

### 6.1 只播放动作

```cpp
TriggerDinoAction(DINO_ACTION_DISCOVER);
TriggerDinoAction(DINO_ACTION_AFFECTION);
TriggerDinoAction(DINO_ACTION_HAPPY);
```

接口只入队，不阻塞调用线程。动作由 `dino_auto` 任务以50FPS执行。

### 6.2 动作与指定音频同时播放

```cpp
int sound_index = flash_audio_find_file("某个叫声音频.opus");
TriggerDinoAction(DINO_ACTION_PROUD_CALL, sound_index);
```

### 6.3 自动根据音频选择动作

```cpp
int sound_index = flash_audio_find_file("咀嚼音效合集 (12).opus");
TriggerDinoSoundAction(sound_index);
```

推荐触摸、语音和服务端事件使用这一接口，避免在业务代码里复制文件名判断规则。

也可以反过来先指定互动动作，再让系统从Flash里自动挑选语义匹配的声音：

```cpp
TriggerDinoActionWithAutoSound(DINO_ACTION_EAT);       // 只会匹配咀嚼声
TriggerDinoActionWithAutoSound(DINO_ACTION_LISTEN);    // 只会匹配脚步声
TriggerDinoActionWithAutoSound(DINO_ACTION_PROUD_CALL);// 匹配较长叫声
```

找不到匹配音频时只执行动作，不会为了出声而播放错误类别。

### 6.4 开机问候

```cpp
InitAutoRun();
TriggerDinoGreeting();
```

开机问候只从5秒以内的叫声中选择，不会在开机时随机播放咀嚼声或脚步声。

### 6.5 传感器调用示例

```cpp
// 摸头
TriggerDinoAction(DINO_ACTION_AFFECTION, touch_sound_index);

// 连续触摸达到奖励阈值
TriggerDinoAction(DINO_ACTION_HAPPY, happy_sound_index);

// 突然的大声音
TriggerDinoAction(DINO_ACTION_STARTLED, startled_sound_index);
```

动作队列满时系统会丢弃最早尚未执行的请求，优先响应用户刚刚发生的互动。

### 6.6 人机互动事件建议

产品默认把用户放在正前方，因此每个互动动作先让IO15回到90°朝前与用户建立联系，再做身体回应。推荐事件映射如下：

| 用户行为 | 动作 | 表演含义 |
| --- | --- | --- |
| 用户靠近、唤醒词 | `DINO_ACTION_DISCOVER` | 先发现用户，再前探和摇尾确认 |
| 摸头或抚摸 | `DINO_ACTION_AFFECTION` | 脸颊靠近、左右轻蹭、舍不得离开 |
| 连续互动或完成任务 | `DINO_ACTION_HAPPY` | 大幅摇尾、脖子画圆，形成奖励高潮 |
| 用户说“叫一个” | `DINO_ACTION_PROUD_CALL` | 先看用户，再蓄力鸣叫和巡视展示 |
| 喂食/NFC食物 | `DINO_ACTION_EAT` | 先看用户手中的食物，再弯到最低处进食 |
| 听到用户呼唤 | `DINO_ACTION_LISTEN` | 冻结、定位、回看正前方等待下一句 |
| 突然敲击或大声 | `DINO_ACTION_STARTLED` | 后缩后鼓起勇气回来确认用户 |
| 长时间无人互动 | `DINO_ACTION_SLEEPY` | 点头、蜷睡、慢呼吸 |

如果以后增加左右方向传感器，可以在进入动作前用方向值决定首次观察方向；现阶段方向随机，但不允许连续三次同向，同时头、颈、尾风格分别随机组合。

## 7. Web试演

设备控制页新增“萌宠动作库”区域，包含八个动作按钮。点击后会自动选择匹配音频并调用：

```http
POST /api/action
Content-Type: application/json

{"action": 0}
```

动作编号与 `DinoAction` 枚举顺序相同，范围为0～7。接口会自动开启自主动作任务，适合在实机上逐个检查拉线方向、动作幅度和外壳干涉。

## 8. 实机调参建议

当前关键帧使用工程定义的标准方向。V3.0实机表演范围为：

- 脖子上下IO17：0°～180°完整行程；
- 脖子左右：0°～180°完整行程；
- 头部左右IO15：0°～180°，90°固定为正前方；
- 尾巴上下IO8：55°～180°，55°为最下安全位、180°为最高位；
- 尾巴左右IO18：0°～180°；动作库包含跨越两侧、单侧轻甩、画圆和配重等随机策略。

首次烧录后建议按以下顺序检查：

1. 先暂停自动模式，用Web滑块确认五路舵机实际方向与文档一致；
2. 依次试演“发现你了”“贴贴撒娇”“雀跃开心”；
3. 检查脖子前探时拉线是否过紧，尾巴快速摆动是否碰壳；
4. 再测试“威风鸣叫”和循环进食；
5. 如果某个方向接近机械极限，应优先缩小该轴关键帧角度，不要扩大PWM脉宽。

软件已经按照大幅度表演设计。IO16、IO17和IO15允许0°～180°；IO18允许0°～180°，IO8限制55°～180°。如果任一轴出现堵转、持续嗡鸣、拉线完全绷直或碰壳，应立即停止并缩小该轴范围。
